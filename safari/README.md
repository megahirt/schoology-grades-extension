# Safari build output

This directory holds the Xcode project generated by Apple's Safari web
extension packager, plus the script that generates it.

- `convert.sh` — generated by `node scripts/build-safari.mjs` on a
  machine without Xcode (e.g. Linux). Run it **on a Mac with full Xcode
  installed** (Command Line Tools alone is not enough). It tries
  `xcrun safari-web-extension-packager` first (new name, WWDC26) and
  falls back to `xcrun safari-web-extension-converter` (older Xcode).
  On a Mac, `node scripts/build-safari.mjs` runs the packager directly
  instead of generating this script.
- `<AppName>.xcodeproj` — generated by the packager on the Mac. It
  contains a native macOS app wrapper with the extension embedded as a
  `.appex`. (Not present on Linux checkouts.)

## After conversion (on the Mac)

1. Open the `.xcodeproj` in Xcode. Set the **Team** on **every** target
   (app + extension).
2. Verify each target's bundle ID — the converter sometimes mangles
   them so the app and extension prefixes mismatch and Xcode refuses
   to build. App: `com.example.schoology-dashboard` (placeholder),
   extension: `…​.Extension`.
3. Strip `browser_specific_settings` / `key` / `side_panel` /
   `offscreen` from the manifest if present, and read the converter's
   compatibility warnings — don't ignore them.
4. Build the containing app's help/settings screen: what the extension
   does, how to enable it (Safari → Settings → Extensions, then allow
   it on schoology.com), a privacy note ("homework data stays on this
   Mac; nothing is sent to a server"), and a support link. Guideline
   4.4: the containing app must have real functionality — it must not
   be blank.
5. Local test: Product → Run, enable in Safari → Settings → Extensions,
   then **grant page access separately** (per-site / Always Allow on
   schoology.com) — enabling is not the same as granting access, and
   the content script never runs until access is granted. Or use the
   quick loop: Safari Settings → Developer → Allow Unsigned Extensions
   (resets every Safari quit) → Add Temporary Extension.
   Debug via Develop → Web Extension Background Pages.

## Distribution

App Store only — there is no separate Safari Extensions Gallery, and
Developer-ID notarized distribution outside the Mac App Store is **not**
treated as viable for web extensions. TestFlight first (100 internal /
10,000 external testers, 90-day builds), then App Store submission.
Review: plan 1–7 days, submit 2–3 weeks early (Oct 2026 reports show
12–22 day tails for first submissions). Updates ride with app updates:
bump `CFBundleShortVersionString` per release and `CFBundleVersion`
per upload.

Full pipeline, Account owner's checklist, and CI notes:
see [`docs/safari.md`](../docs/safari.md) in the repo root.
